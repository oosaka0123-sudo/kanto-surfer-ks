# 個別ページ予報UI仕様 v1

## 目的
関西版の個別ページで使っている「時間別予報」の見せ方を基準に、関東版の個別ポイントページでも予報を同じ操作感で表示する。

時間別予報だけでなく、週間予報も横スクロール式に統一する。

## 基本構成
個別ページの予報セクションは次の2表示を持つ。

- `時間別`
- `週間`

タブ切替後もフレーム、配色、行見出し、スクロール操作の考え方は共通にする。

## 時間別予報
現行の個別ページを基準にする。

### 上段
- 波高推移の折れ線
- 風速の棒グラフ
- 時刻に沿った横方向の時系列

### 下段
左側に項目名、右側に時刻列を並べる。

推奨行:
- 時刻
- 天気
- 波の高さ
- 周期
- 風
- 必要に応じて、うねり方向 / 波向 / 降水

時刻列は横スクロール可能にする。

## 週間予報
### 方針
週間予報も縦長カードの積み上げにはしない。
時間別予報と同じ表形式を保ち、**日付を横方向に並べてスワイプする**。

### 上段グラフ
時間別予報と同じデザイン言語で、日ごとの傾向を表示する。

- 波高: 折れ線
- 風: 棒グラフ
- X軸: 日付

週間表示で使う値は、その日の代表値の定義をデータ仕様側で確定してから接続する。未確定の平均値・最大値等をUI側で勝手に生成しない。

### 下段テーブル
左側の項目列を固定し、日付列だけ横スクロールする。

推奨行:
- 日付
- 天気
- 波の高さ
- 周期
- 風
- 必要に応じて、うねり方向 / 波向 / 降水

日付列の例:

```text
        9/13   9/14   9/15   9/16   9/17 ...
天気      -      -      -      -      -
波高      -      -      -      -      -
周期      -      -      -      -      -
風        -      -      -      -      -
```

`-` は仕様例のプレースホルダーであり、予報値ではない。

## 横スクロール仕様
### スマホ
- 指で左右スワイプ。
- 1列の目安幅: `92px〜110px`。
- 画面内に約3日分が見え、右側に次の日が少し見える構成を優先する。
- `scroll-snap-type: x proximity` を基本とする。
- 慣性スクロールを妨げない。
- 左の行見出し列は `position: sticky; left: 0;` で固定する。
- 横スクロール領域内でページ全体の縦スクロールを阻害しない。

### PC / タブレット
- トラックパッド、Shift+ホイール、ドラッグ相当の操作に対応する。
- 必要なら左右矢印ボタンを補助UIとして付ける。
- 日付列を無理に全幅へ引き伸ばさず、一定幅を維持する。

## 現在日 / 選択列
- 今日の列だけアクセント背景を付ける。
- 時間別では現在時刻に最も近い列を同様に強調してよい。
- 強調色はサイト共通の赤系アクセントを使う。
- 色だけに依存せず `aria-current` 等も使う。

## データ接続ルール
- UIはOpen-Meteo raw値を直接表示しない。
- 公開用データ契約/正規化済み出力を入力とする。
- 検証前の値を実測・確定値のように表示しない。
- 波高・周期・風などの単位を必ず明示する。
- 欠損時は推測せず `--` または「データなし」とする。
- 週間の代表値集約ロジックはフロント側に埋め込まず、データ層で一意に決める。

## アクセシビリティ
- 時間別/週間タブはキーボード操作可能にする。
- 横スクロール領域には分かるラベルを付ける。
- グラフだけで情報を完結させず、同じ値を表側でも確認できるようにする。
- 天気をアイコンだけで表現せず、`aria-label` またはテキストを持たせる。

## 実装時の共通コンポーネント方針
時間別と週間で別々の巨大DOMを作らず、同じ予報テーブルコンポーネントへ次を渡す構成を優先する。

- `mode = hourly | weekly`
- `columns`
- `rows`
- `currentColumn`
- `chartSeries`

これにより、配色、sticky列、横スクロール、欠損表示、アクセシビリティを共通化する。

## 受入条件
- スマホで週間予報を左右スワイプできる。
- 左の項目名は固定されたまま、日付だけ横に動く。
- 時間別予報と週間予報で見た目・操作感が揃っている。
- 今日の列が判別できる。
- 7日以上表示してもレイアウトが潰れない。
- 縦スクロールと横スクロールが競合しない。
- 欠損値を捏造しない。
- 実データ接続前でも表示構造だけテストできる。
