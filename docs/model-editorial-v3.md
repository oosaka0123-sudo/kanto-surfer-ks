# 関東9地点・100文字記事 編集レイヤー v3

## 目的
トップBEST9の順位は `scripts/render_model_rankings.cjs` がモデルデータから確定的に作る。文章だけをChatGPTの既存朝7:30／夜19:30タスクで編集し、トップ9本・個別9本それぞれ日本語90〜120文字に整える。生成AIの従量課金APIは使用しない。

## 書き込み先
- 朝（当日の記事）：`content/model-editorial/morning/YYYY-MM-DD.json`
- 夜（翌朝の記事）：`content/model-editorial/evening/YYYY-MM-DD.json`（ファイル名は翌日の対象日）
- 9地点のID・地形条件：`config/representative-spots.json`を正本
- ソース：本番の`data/{id}.json`を確認。GitHub Pages成果物も許可。全地点の朝09:00 JSTモデル値を同一日時で照合する。

## JSON契約
```json
{
  "schema_version": 1,
  "status": "ready",
  "slot": "morning",
  "date": "対象日（YYYY-MM-DD）",
  "generated_at": "記事執筆時刻（JST ISO秒＋09:00）",
  "model_generated_at": "参照したモデルJSONの実際の生成時刻",
  "basis": "model_forecast",
  "articles": {
    "kugenuma": {
      "home": "90〜120文字のトップ用文章",
      "detail": "90〜120文字の個別ページ用文章",
      "wave_9_m": 0,
      "period_9_s": 0,
      "wind_label": "実データの9時風向"
    }
  }
}
```
上の数値0やテキストは**形式例**であり実際の予報ではない。9地点すべてをarticlesに入れる。

## 編集規則
- 9時のモデル波高と周期を文章に書く場合は数値の直書きではなく `{{wave_9_m}}m` と `{{period_9_s}}秒` を使う。表示時に最新の検証済みモデル値（波高小数2桁・周期小数1桁）へ展開する。風向は `{{wind_label}}` も使用可能。
- 90〜120文字の検査はプレースホルダーを数値に展開した後の最終表示文に適用する。元のテンプレート文字列が120字超でも、表示文が条件内なら可。
- 実際の波サイズ・実況・点数・安全性を捏造しない。波高は海上モデル値でありサーフィンのブレイクサイズではない。
- 海岸ごとの有効なうねり、風、潮の変化、適したチェック時刻、注意点の中から、本当に重要なことだけを書き分ける。地点名だけ置き換えた定型文は禁止。
- トップ用は順位選びの判断材料、個別用は当該地点でのチェック項目を中心にして全文コピーしない。
- 1文字ずつ切る機械的な省略を禁止。9地点×2本の文字数、表現重複、数値・方向の不整合、出典時刻を確認する。
- JST当日・前日夜の対象日を厳守し、夜は予報のみ。危険情報は公式に確認したものだけ言及。
- 編集が失敗・未保存・モデル値と矛盾・古い場合、ランキングを止めず**プログラムの短文に戻す**。順位そのものはAI編集不可。
- `ready` は機械的掲載条件を満たす意味であり、実在の人間による確認済みとは表示しない。

## 掲載側検証
- 90〜120文字、トップと個別の別文面、9地点のID・日付・slot・生成時刻
- 参照波高との誤差0.25m以内、周期2.5秒以内、風向方位の差67.5度以内。9地点の1つでも検証不一致なら**編集ファイル全体を使わず**モデル由来の短文へフォールバック
- 投稿はGitHubへ保存し再取得・SHA検証。ロリポップ本番へ直接書かない。既存の公開ワークフローがソース成果物を検査して同期する。
